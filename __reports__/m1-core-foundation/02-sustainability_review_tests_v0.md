# M1 test suite: sustainability review, v0

Verdict: the suite is fast (about 11.5 s of test time) and its guards are well named and well explained, but the two largest files (store.rs, cache.rs) forked the campaign-builder, snapshot and copy helpers instead of using tests/common, so every cross-cutting fix (the Windows path key was one) has to be made in 3 to 4 places and was already missed in 2; fix that before M1 merges, and cull about five cache rows that were shaped by mutants rather than by actors.

## Measured suite times

One run: `cargo test --workspace --locked` with a warm shared target dir (`real` 19.8 s wall, including cargo's no-op build check). Load average at start 5.48 (1 min), 18.75 (5 min), 32.5 (15 min); at the end 4.86. The machine was coming down from a heavy load, so these are upper bounds.

| binary | tests | finished in |
|---|---|---|
| crash_prefix | 1 | 4.15 s |
| crash_kill | 1 | 2.62 s (25 rounds of 30..150 ms sleeps, wall clock by design) |
| store | 27 | 1.96 s |
| lock | 5 | 1.05 s |
| rdm-mcp stdio | 14 | 0.71 s |
| codec | 6 | 0.46 s |
| cache | 8 | 0.40 s |
| fs | 3 | 0.17 s |
| everything else (schema, intent, unit) | 36 | under 0.02 s each |
| sum | | about 11.5 s |

The must-run set is at 40 percent of the 30 s budget. Headroom is fine today; the growth shape is the concern (T9).

## Section: the hot-cache fix-round rows and the crash-test additions

Method: for each row, who produces the input, and is the class already covered by an existing guard. The coordinator's note holds: these rows are shaped by which signature component the mutant dropped, not by an actor. The guard for the class is "a cached read equals a cold read for every way a file can change without the directory changing" and the cheapest honest expression of it is a small table of actors.

| row | site | real actor? | class already covered? | verdict |
|---|---|---|---|---|
| aged same-size rename-over keeping mtime | cache.rs:627-650 | Yes: rsync with `--times`, `git checkout` with preserved time, a synchroniser. Identity (inode) is the only change. | Same class as "an aged file replaced by another version": the table below. | Keep as a row, folded. |
| aged size-only edit with mtime restored | cache.rs:652-664 | Weak. An editor that restores mtime after a grow (some IDE "preserve timestamps" saves, `touch -r` after append) exists; it is the same actor as the next row with a different size. | Covered by the touch-r row, which also restores the mtime. The two differ only in which signature component the mutant drops. | Fold into the touch -r row (one row with a size change). Delete the separate row. |
| `touch -r` after same-size in-place edit | cache.rs:665-681 | Yes: `touch -r`, `cp -p`, rsync `-t`, backup restore. Unix only; ctime is the only witness. | Not covered by anything else. | Keep (the real class "an actor restores the mtime"). |

Proposed cull, in effect:
- Delete: the "size-only edit with mtime restored" row (fold into the `touch -r` row as a size variant).
- Fold into one table-driven row: the two racy rows (native and ctime-blanking hook); the aged rename-over, `touch -r` and the folded size row become three entries of one "an aged file changes without the directory changing" table. Net: 5 blocks become 4 entries of one table with one `age()` and one `rewrite_in_place` helper.
- Fold: `a_write_judges_the_files_it_touches_against_the_disk` into the `stale_replace_changes_nothing` class run through a warm cache.
- Keep as real classes: `a_rebalance_rewrites_a_sibling...` (renamed as the sibling-write class), the vanish guard, the create-over-foreign-bytes guard, `facts()`.
- Not culled: the git-checkout, comment/amendment-directory and unknown-key rows in `cached_read_equals_cold_read`; each has a real actor.

## Deliberate, keep

- codec.rs fixtures hand-written from the contract documents ("Nothing here asks the encoder what canonical is"); do not generate them from `encode`.
- The `jq` plus `shasum` independent oracle (T6): keep its independence, change only how it is delivered.
- crash_prefix `oracle()`: pre and post states come from running the operation, never from replaying the log (crash_prefix.rs:~505 doc); keep it free of the replay code.
- `facts()` reading JSON plainly and walking `parent_id` instead of calling the store's tree code.
- `RecordingFs` and `replay_prefix` in src/fs.rs used by the tests: the Pillai method needs one recorder; there is no second mechanism.
- Child tests that re-execute the test binary (no helper binary to build or version) and kill with SIGKILL for real; the lock and atomic-replace tests with real processes and real `fs4` locks.
- crash_kill: wall-clock sleeps and unseeded interleavings, with the doc stating that no seed is tuned to a bug.
- `#![allow(dead_code)]` in tests/common modules (each test binary compiles its own copy).
- The codec's separate proptest persistence path if the team wants regressions committed; it only needs to be the same for all three proptests (T4).
