# M1 core foundation: sustainability review of product code (src), v0

Scope: `crates/rdm-schema/src`, `crates/rdm-engine/src`, `crates/rdm-mcp/src` on `feat/m1-core-foundation`. Not correctness; not tests.

**Verdict: sound seams and mostly consistent conventions; the debris is small (one dead stub, duplicated temp-file and effect-replay code, stale crate docs), but the write and read paths are O(N) per request with whole-campaign clones, and there are two public front doors (`Store`, `CachedCampaign`) that M4 should not inherit. Fix S3, S4, S5, S7 (layout constants) before merge; the scaling items can wait for M2/M4 but must be recorded.**

Evidence base: one clippy pedantic+nursery run (classes only), `cargo tree -d` (no product-relevant duplicate), line-range reads, colgrep hits. Costs below are scaling arguments from the code, not measurements.

## Deliberate, keep

- `RealFs` and `RecordingFs` behind the one `Fs` trait: the recording fs is the crash-matrix oracle; keep it independent of `publish`/`write` (only gate it, S11).
- `order.rs` has its own base-62 digit table; the id alphabets in `rdm-schema/src/ids.rs:18,20` are 32-character by contract, so these are different alphabets, not a duplicate.
- `cache::digest` (std `DefaultHasher`, process-local change detection) beside `rev.rs` SHA-256 (a contract value): different jobs. Keep both, but the `digest` doc should say "not stable across Rust releases".
- Direct `SystemTime::now()` at `write.rs:290` and `cache.rs:332,356`: the racy window compares with file mtimes, which come from the real file system, so it must not use the injected `Options.clock`. Add a one-line comment saying so.
- Hand-written `Display`/`Error` impls (`StoreError`, `IdError`, `NameError`, `LockError`, `MintError`): consistent across crates and avoids a dependency; not an outlier.
- `clock.rs` hand-rolled RFC 3339 (no `chrono` dependency) and the `Unique` duplicate-key visitor in `codec.rs`: small, and the alternatives pull in dependencies.
- `version.rs` layered decode (`FormatLayer`, `Nothing`, `V0_1`): the intended version chain of responsibility.
- `redo` vs `redo_fresh` differ in meaning (recovery is idempotent, a fresh write is not): share the dispatch (S4) but keep both policies.
- The `rdm-mcp` spike is self-contained by design; do not wire M1 into it, replace it in M4.
